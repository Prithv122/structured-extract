# Committed data

Everything here is generated by `structured-extract` and checked in on purpose:
the benchmark has to replay from a clean clone with no network, no DuckDB
extension downloads and no API key.

```bash
uv run structured-extract oracle verify   # offline
uv run structured-extract corpus verify   # offline
uv run structured-extract corpus stats
```

To rebuild (needs network once, for the pinned docs checkout):

```bash
uv run python scripts/fetch_source_docs.py
uv run structured-extract oracle build
uv run structured-extract corpus build
```

## Files

### `oracle/settings.jsonl` — 280 rows, 274 distinct settings

What the binary says a setting *is*. One row per name reported by
`duckdb_settings()`, with the extension that introduced it.

`duckdb_settings()` emits **both** spellings of an alias pair as full rows — one
carries the `aliases` list, its twin is bare — so 280 rows describe 274 settings.
The six pairs are `max_memory`/`memory_limit`, `threads`/`worker_threads`,
`username`/`user`, `profile_output`/`profiling_output`,
`checkpoint_threshold`/`wal_autocheckpoint`, `default_null_order`/`null_order`.

| extension | settings |
|---|---:|
| core | 160 |
| `httpfs` | 34 |
| `mysql` | 31 |
| `postgres` | 24 |
| `azure` | 18 |
| `iceberg` | 8 |
| `spatial` | 3 |
| `delta` | 2 |
| `aws` | 0 |

`aws` is probed and listed at zero on purpose, so a reader can see it was checked
rather than forgotten.

### `oracle/observed_values.jsonl` — 280 rows, **not ground truth**

`duckdb_settings().value` reports what the *build machine* was running:
`threads` is that host's core count, `max_memory` a fraction of its RAM,
`Calendar` and `TimeZone` its locale. The reference table documents the rule
("System (locale) calendar"), not a value.

Keeping `value` out of `settings.jsonl` is what makes the oracle reproducible on
another machine — and keeps a benchmark from scoring models against one laptop's
core count. The file is stamped with `host_platform` so its numbers can never be
mistaken for portable ones.

### `oracle/docs_reference.jsonl` — 169 rows

The generated configuration reference tables from
`docs/current/configuration/overview.md`, parsed strictly (see
`src/structured_extract/docs_table.py`). This is the ground truth for a
setting's **documented default**; the binary is the ground truth for its name,
type and scope.

`default_is_empty_cell` separates "documented as the empty string" (23 rows)
from "no default documented" (8 rows) — the upstream generator writes an empty
cell for the first and the literal `NULL` for the second.

### `corpus/corpus.jsonl` + `corpus/documents/*.md` — 120 documents

Heading sections of real documentation pages, sampled with seed `20260919`.
The manifest carries a `sha256` of every document and
`structured-extract corpus verify` re-hashes them, so a silently edited document
is a test failure rather than a quietly different benchmark.

| bucket | documents | sampled from |
|---|---:|---|
| `narrative-signal` | 50 | 152 sections across 75 pages |
| `narrative-distractor` | 10 | 260 sections across 123 pages |
| `extension-signal` | 19 | 31 sections across **19** pages — a census, not a sample |
| `extension-distractor` | 6 | 66 sections across 29 pages |
| `reference` | 35 | 169 rows of one generated page |

`mentions` records every known setting name found in the text. **A mention is not
a claim that the document documents the setting** — `extension-0001` says "will
count towards the memory limit" in passing, which no oracle can distinguish from
a page that actually specifies `max_memory`. That gap is what the hand-labelled
recall set exists to measure.
